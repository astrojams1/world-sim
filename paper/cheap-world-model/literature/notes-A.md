# Theme A notes — VLM/LLM + code/tools for visual & spatial reasoning; VLM spatial limits

Sources: `refs-A.bib` (25 entries, all resolved via arXiv API), `abstracts-A.md`. Full texts read (arXiv HTML): 2605.12586, 2502.06787, 2606.12830, 2406.09403, 2303.08128, 2606.20515, 2404.15228, 2601.13029, 2606.13673, 2603.00905. Everything below is from those records; no numbers from memory.

Our work, for reference: training-free; gpt-5-mini (low reasoning) + hosted Python sandbox preloaded with a classical CV helper module (two-camera self-calibration from the room's hexagonal silhouette, symmetry-resolving alignment, blob detection, triangulation, render-and-compare refinement of position/size/orientation, silhouette+shading shape tests); two uncalibrated 640x480 views of a unit-cube room with 2-12 red/blue spheres and cubes; output = explicit JSON scene state (shape, colour, size, position, Euler rotation per object); frame- and symmetry-invariant metric; 99.5/100 mean on 10 rooms, 22 s, $0.032/scene ($0.03 of it sandbox), 6.3k tokens; 95.9 at 8 objects; LLM's marginal contribution over the classical pipeline measured and small.

## (b) Closest works

**SpatialClaw (cho2026spatialclaw, 2606.13673).** Training-free agent whose action interface is code: for each example a dedicated stateful IPython kernel is preloaded with the input frames (<=32 frames, long edge <=768 px), a `tools` module (`Reconstruct` = Depth Anything 3 returning per-frame depth, intrinsics, extrinsics, point maps; `SAM3` masks; `vlm.locate` grounding; `vlm.ask_with_thinking`; Mask/Geometry/Time utilities), NumPy/SciPy/Matplotlib, `show()` to push images back into the model context, and `ReturnAnswer()`. A separate planner LLM (no images) writes a plan; the main agent writes one cell per step, sees stdout/variable summaries/rendered images, and iterates under step, failure and tool-call budgets with AST-based sandboxing and CoT fallback. Evaluated on 20 spatial-QA benchmarks (Acc / MRA), six open backbones (Gemma4, Qwen families); 59.9% average, +11.2 over the prior spatial agent; ablation shows the code interface beats structured JSON tool calls and single-pass code (VADAR, pySpatial classed as single-pass) with identical tools, and that "no perception tools, code only" still gains over no-tool. Failure analysis: geometric reasoning errors lead, perception second. **Relation:** this is the same systems pattern as ours (persistent kernel + preloaded primitives + visual feedback + revise). Differences: (i) target is QA answers, not an explicit per-object metric state; (ii) primitives are learned monocular/multi-view reconstructors, ours is a classical closed-form pipeline (silhouette self-calibration, triangulation, analysis-by-synthesis); (iii) no render-and-compare against a renderer of the hypothesised state; (iv) no cost or latency numbers at all; (v) we quantify the LLM's marginal contribution vs the pipeline alone.

**pySpatial (luo2026pyspatial, 2603.00905).** Zero-shot visual programming: an MLLM (GPT-4o by default; GPT-4.1-mini on full MindCube "due to budget constraints") generates one Python program against a fixed API of spatial tools — 3D reconstruction (VGGT), camera-motion description, novel-view synthesis — from an image sequence + query. Results: 58.56% on full MindCube (+12.94 over GPT-4.1-mini); on MindCube-1k GPT-4o 42.3 -> 62.7 with pySpatial; Omni3D-Bench +3.8 over VADAR, +17.5 over ViperGPT; Unitree Go1 navigation demo. **Relation:** multi-view -> 3D via code, training-free, robotics-motivated. Differences: no explicit object state or size/orientation, learned reconstructor, single-pass program without visual feedback loop, no cost/latency.

**VADAR (marsili2025visual, 2502.06787).** Training-free multi-agent program synthesis for 3D spatial queries from a single image. Stage 1 builds a Pythonic API (Signature agent, Implementation agent with weak-ICL, Test agent = interpreter, depth-first dependency resolution) from ~15 unlabeled queries; Stage 2 a Program agent writes code per query, re-generated up to 5x on exceptions. Predefined modules: Molmo/GroundingDINO `loc`, SAM box size, UniDepth `depth`, GPT-4o `vqa`. Benchmarks: CLEVR (1,155 Qs; 2-10 objects, 3 shapes) and new Omni3D-Bench (500 free-form metric queries on Omni3D). Table 1 totals: VADAR 53.6 CLEVR / 40.4 Omni3D vs GPT-4o 58.4 / 42.9, ViperGPT 26.2 / 26.7, VisProg 31.2 / 13.5. Oracle vision specialists: 83.0 / 94.4 — "main limitation is the vision specialists' performance". Runtime (A100): Signature 20.5 s per 10 Qs, Implementation 37.2 s (one-off), Program 6.5 s/Q, Execution 35.7 s/Q. No dollar cost. **Relation:** LLM + code + CV modules on CLEVR-like primitive scenes; the oracle analysis is the same decomposition argument we make (perception module quality, not LLM orchestration, bounds accuracy). Differences: single view, monocular metric depth, QA output, heavier multi-agent pipeline, ~42 s/Q vs our 22 s/scene for a full state.

**SpatialBabel / Code-CoT (liu20263d, 2605.12586).** Benchmark of 1,000 single-view 512x512 renders with 3-20 primitives (cubes, spheres, cylinders, cones, tori, pyramids; 10-colour palette; no major occlusion; 5 tiers T1=3 ... T5=20 objects) plus 405 Hypersim scenes. 14 VLMs are prompted to emit executable scene code in six languages (Three.js, Unity C#, Blender Python, Open3D, canonical JSON, Scene-Language DSL) specifying class, position, scale, rotation; the code is parsed (not executed) and Hungarian-matched; Reconstruct Score = 1/5 (parse rate + F1 + class acc + position fidelity + scale fidelity) with fidelity = max(0, 1 - clipped normalized RMS). Findings: F1 varies up to 5.7x across output languages for the same model; Code-CoT (training-free: reconstruct in code, then answer) lifts Primitive-QA by up to +6.4 (Gemini-2.5-Pro) and CV-Bench-3D by +5.0/+5.9 (Claude); S3-FT LoRA on self-parsed Three.js output takes Qwen3-VL-8B F1 0.73 -> 0.86. **Relation:** closest *task* — primitive scenes to explicit scene state with position/scale metrics. Differences: purely open-loop (no execution, no rendering, no comparison to the image), single view, no camera calibration, orientation not scored, positions only "approximate"; no cost. Our contribution can be framed as closing their loop with a sandbox and classical geometry to push position/size/rotation to near-exact.

**S-Agent (dai2026s, 2606.20515).** VLM as semantic planner over multi-view images/video with structured tool calls at three levels: L1 frame selection + grounding (open-vocab detectors), L2 multi-view geometric lifting (depth, metric coordinates, camera poses, BEV/novel views; cites VGGT, Depth Anything 3), L3 spatial experts (count, measure, orientation, relative position). Two memories: Scene Memory (persistent entity-centric scene state: aliases, frames, visual evidence, accumulated geometric attributes) and Agent Memory (tool history). Training-free with GPT-5.4 / Gemini 3 Pro: MMSI-Bench beats GPT-5.4 by 4.5 pts and Gemini 3 Pro by 1.2; ViewSpatial 60.0% (+14.4 over GPT-5.4); ReVSI 58.8. Then 292k SFT trajectories (S-300K) -> S-Agent-8B (MMSI 31.1 -> 41.6). Ablation: L1 evidence 45.6 -> 49.0 etc. **Relation:** explicitly maintains an "evolving scene state" from multiple views, training-free, robotics-flavoured. Differences: scene state is an internal memory never scored as a reconstruction; QA metrics only; learned geometry; JSON-style tool interface; no cost/latency; frontier-size planners rather than a mini model.

Also relevant but not top-5: **IG-LLM (kulits2024re)** is the trained counterpart of our task (CLEVR image -> full scene program with location/orientation via a numeric head; L2 pos error 0.16-0.21, >99% attributes after 4k training images) — a natural point of comparison to show training-free parity; **Think3D (zhang2026think3d)** uses Pi3 point clouds + iterative view selection, training-free for GPT-4.1/Gemini (+7.6/+13.0 on MindCube-1K) but QA only.

## (c) Threats to novelty

1. **"Training-free VLM + stateful Python kernel preloaded with perception/geometry primitives, with visual feedback and revision" already exists: SpatialClaw (2606.13673).** It even includes a `Reconstruct` tool returning intrinsics/extrinsics and a `show()` render-back channel, and ablates code-as-interface vs JSON tools vs single-pass. We cannot claim the systems pattern. What remains ours: explicit metric scene-state output and its evaluation, classical (non-learned) self-calibration/triangulation/analysis-by-synthesis primitives, a mini model, dollar cost, and the LLM-marginal-contribution measurement.
2. **"VLMs emit executable primitive scene code (position/scale/rotation) from renders of cubes/spheres, evaluated with matched position/scale fidelity" exists: SpatialBabel (2605.12586).** They have the benchmark and the metric family; their models are open-loop and single-view. Our claim must be about closing the loop (execute, render, compare, refine, two-view calibration) and about accuracy level (near-exact vs "approximate"), not about the idea of primitive-scene-as-code.
3. **Multi-view training-free agents that maintain an explicit "scene state" from tools exist: S-Agent (2606.20515), pySpatial (2603.00905), Think3D (2601.13029).** All use learned reconstructors (VGGT/Pi3/DA3) and output QA answers. Our differentiator is that the state itself is the deliverable and is scored; we should say so plainly and avoid claiming "first to build a scene state with a VLM agent".
4. **LLM + code + CV modules on CLEVR-style scenes with the "LLM is fine, vision modules are the bottleneck" analysis exists: VADAR (2502.06787).** Their oracle experiment (83.0/94.4) pre-empts a generic version of our "the LLM's marginal contribution is small" message; ours is different in direction (we show the pipeline alone nearly suffices) but must be positioned against it.
5. **Trained single-view inverse graphics on CLEVR already reaches L2 ~0.16 and >99% attribute accuracy: IG-LLM (2404.15228).** A reviewer will ask why a training-free 3-cent pipeline matters when a fine-tuned 7B model does it; answer must rest on no-training, two-view metric calibration from uncalibrated cameras, orientation, and per-scene cost — and ideally a direct comparison on comparable scenes.
6. **Per-sample cost reporting is rare but not absent:** Visual Sketchpad reports $0.06-0.13 and 12-27k tokens per sample on GPT-4o (2406.09403). Our $0.032 / 6.3k tokens is a legitimate comparison point, but "first to report cost" would be false.
7. Robotics framing overlap: pySpatial (robot navigation demo), TIGeR (cm-level manipulation, trained, uses depth sensors + calibration), S-Agent. None produce a simulator-ready explicit state from two uncalibrated RGB views, which is our defensible niche.
